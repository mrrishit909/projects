Portfolio_01Business intelligence · 2026-09

Florida Flight Delays

A Power BI report on 635,459 flights leaving Florida airports: who's on time, when, and why flights run late.

Problem
US DOT publishes every flight's on-time record as about 6.5 million rows a year with 109 columns. Travellers and operators want four plain answers: which airports, which airlines, which hours, and why.
What I did
Solo project. I built the star schema (635,459 flights, four dimensions), the DAX measures with a whole-Florida benchmark, the report in Power BI Service, and a pandas script that recomputes every card to test it.
Result
75.5% on time; time of day matters about twice as much as the airline, and late-arriving aircraft cause 42.5% of delay minutes. The interactive version on this site is a web preview of the same model.

Portfolio_02Data engineering · 2026-10

Retail Pipeline in dbt

A real online retailer's 1.07 million invoice lines turned into tested, documented tables (sales, customers, products, cohorts) with dbt and DuckDB.

Problem
Raw sales exports are never analysis-ready: duplicate rows, postage mixed with products, cancellations hiding inside sales. Every analyst cleans the file again, differently.
What I did
Solo project. I wrote the staging, intermediate and mart layers in dbt on DuckDB over 1.07 million invoice lines, a seed of business rules, 31 data tests (five written for this data) and the generated lineage docs.
Result
Net sales £18.18M after £1.46M of cancellations; champions are 25.1% of customers and 70.8% of revenue. Runs on demand on a laptop, no scheduler or warehouse.

Portfolio_03SQL analysis · 2026-10

How Chicago Rides

A year of Chicago bike-share trips (6.1 million rides) in SQL: how members and casual riders differ, and where a membership campaign should go.

Problem
Chicago's Divvy bike-share has annual members and casual riders. How do they use the bikes differently, and where would a membership campaign reach the most casual riders?
What I did
Solo project. I loaded 6.1 million trips into SQLite, wrote one SQL file per question (CTEs, window functions, indexes), and a plain-Python recount that must agree exactly with every SQL answer.
Result
Members ride 65% of trips and commute at 8:00 and 17:00; casual riders own the lakefront on summer weekends (Navy Pier: 75.9% casual). The campaign recommendation follows from the patterns, not a tested result.

Portfolio_04Forecasting · 2026-10

US Retail Sales Forecast

Forecasting monthly US retail sales: the seasonal pattern, a fair test of five methods on months they hadn't seen, and the next 12 months with honest ranges.

Problem
Monthly US retail sales swing hard with the calendar. A forecast has to get the seasonal shape right, and it is only worth something if you know how wrong it tends to be.
What I did
Solo project. I built the pipeline on Census data from 1992 onward: seasonal indices, five methods, a rolling-origin backtest, and ranges calibrated on the backtest's real errors.
Result
The ETS + SARIMA average scored 1.81% MAPE, 35% smaller errors than 'same month last year'. The calibrated 80% range is about 40% narrower than the models' own.

Portfolio_06Data engineering · 2026-10

The Dashboard Is Wrong and No Job Failed. Where Did It Break?

A monitoring system for a data warehouse. When a source quietly stopped sending one kind of record, every pipeline still reported success; this flagged the 10 affected tables and dashboards, raised them as one incident, and named the source table as the cause. Across 108 planted failures it put the true origin first 94% of the time, against 31% for blaming the loudest alert.

Problem
A source quietly changes what it sends. Every job still finishes green, and the revenue dashboard is wrong. Can software notice the same morning, say what else is affected, and point to where it started?
What I did
Solo project from a written blueprint. I built the Python and PostgreSQL service: lineage discovery (72 assets, 82 links), daily profiles, anomaly detection against each table's own history, incident grouping and root-cause ranking, with 34 tests.
Result
Across 108 planted failures the true origin ranked first 94% of the time, against 31% for blaming the loudest alert. The warehouse is simulated, so every result is checked against a known answer.

Portfolio_07AI-enabled software · 2026-10

Ask the 10-K

An LLM assistant that answers questions from five companies' SEC annual reports, cites the passage behind every fact, and says when the answer isn't there.

Problem
A 10-K runs to hundreds of pages. A chatbot answers fluently, but a fluent wrong number is worse than no answer. Can an LLM answer only from the filings, cite the passage, and admit when the answer is not there?
What I did
Solo project. I parsed five companies' latest 10-Ks from SEC EDGAR into 730 passages, compared keyword, embedding and hybrid search, and graded 30 questions against XBRL figures.
Result
20/20 money answers within 0.5% of XBRL with the figure in the cited passage, 5/5 correct refusals, $0.10 for all 30. The demo shows recorded answers; this site never calls an API.

Portfolio_08Financial modelling · 2026-10

Costco Model in Excel

A driver-based forecast and DCF built from Costco's SEC filings: a real Excel workbook with 231 live formulas, three scenarios, a sensitivity grid and a sheet that checks itself.

Problem
Excel is still where most financial analysis happens, and a model is only as good as how it is built: inputs apart from formulas, scenarios that switch, checks that catch mistakes.
What I did
Solo project. I built the six-sheet Costco workbook from SEC XBRL history: scenario switch, driver-based forecast to FY2030, DCF with a 5 × 5 sensitivity grid, and six self-checks.
Result
231 live formulas; the base case runs from $194 to $399 a share across the grid, so the grid is the result to read. A modelling exercise, not investment advice.
